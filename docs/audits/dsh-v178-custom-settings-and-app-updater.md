# 定制版设置导航与上游 APK 更新入口整改

## 根因与产品约束

工作分支基于 DSHA 进一步修改，包含 Android 宿主、固定 DSH 运行时与移动 UI 补丁。原 DSHA 官网更新清单仅约束上游发行包的版本、安装变体、大小、校验和及签名；即使签名一致、versionCode 较新，也**不能**证明新 APK 保留本项目的定制功能和现有数据迁移能力。因此 **不应让用户直接下载和安装上游发行 APK**。

## 处理

- 更新策略 `UpdatePolicy.appUpdateEnabled()` 当前永久返回 false，直到另行开发并验收属于本工作分支的受信分发、变更与签名策略；保留底层原升级代码以便历史兼容 / 评审，而非保持生产入口。
- 主页不再注册 `UpdateEngine`、自动检查或展示更新 Snackbar；设置页删除更新入口和自动更新开关。旧更新页面启动会明确拒绝，旧应用更新下载服务取消保留任务，`UpdateEngine` 禁止检查、下载、恢复下载和返回已验证 APK，`UpdateRepository` 拒绝申请 APK 安装。
- **保留** `InstallFragment` 中的离线环境组件检查、修复、受管环境安装差异审核、回切和中断维护恢复。这些是安装 APK 之后的本机状态保护，**不是**从官网拉取未知 APK。
- 主页底栏由 4 栏减至 3 栏（启动 / 插件 / 设置）。终端移至设置 → 高级工具，使用原有的 `PtyTerminalFragment.preferred` 与异常状态回退；原 `open_terminal` 直接打开同一终端，仍有设置页返回栈。
- 设置首页直接列出模型与接口、运行与显示、数据与备份、设备授权、高级工具。安装检查和诊断移至高级工具，悬浮条在设置首页统一打开原 `OverlayFragment`；配置子页移除重复模型、数据、悬浮设置、项目链接和检查更新入口。
- Standard 的网页内核固定 System WebView，隐藏单项选择。Low 仍保留多内核选项。
- 原配置页的本机兼容 API Key 和 DSH 模型服务商 API Key 是两种独立存储，**没有**为了去重删除兼容密钥和读写逻辑，而是修改中英语义提示。
- 原配置页有一个 UI 隐藏、保存时却被写成 false 的静态加载器开关；去掉该隐藏控件和写入，以防无关设置保存时覆盖旧偏好。保留 proot/bxroot、DNS、固定端口、LAN、no-seccomp 等高级能力。

## 验收边界

- GitHub Actions 需要完成源码、资源、Standard/Low 测试和 APK 构建；UI 静态核对不是设备验收。
- 需要再次检查新高级工具页（终端/环境/诊断）、首次进入设置、返回键、横竖屏、语言及旧 Intent。
- 本分支仍为 PR #2 Draft；不发布 APK、不合并 main、不操作真实数据、不把临时 Debug 签名包用于生产覆盖。实际 BXROOT+Ubuntu+DSH 0.2.1-rc.2 冷安装、既有会话迁移、OEM 限制和 E7E3 正式签名仍待单独验证。
