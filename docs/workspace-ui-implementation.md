# 工作区界面落实记录

本轮用户确认会话预览后授权落实实际界面，并要求保留原功能和原有代码职责。

## 功能归属

- 模型按钮继续使用 rc2 ModelDirectory 的加载、选择、会话写锁检查、错误重试与通知。保留原目录搜索、提供方分组、模型能力提示、扩展标签和键盘导航。手机仅替换根面板的展示；目录页仍是原组件。
- 强度滑条只使用当前目录返回的 effortChoices，保存继续调用原 chooseEffort/select。草稿只在菜单中存在；关闭不提交强度。不同模型不得合成未声明档位。
- 回复后的复制、赞、踩、分享、本轮用量，以及完成/运行/失败状态，继续由原聊天节点渲染。
- 底部活动、速度和累计用量继续使用原会话投影。缓存另开详情入口，保留缓存写入及原计费分母；本轮用量与累计用量不混用。
- 上下文环、百分比、容量和分类详情继续由原 ContextMeter 渲染。移动插件针对旧版本的环和速度覆盖布局，在语义化统计组件上退休，不能移动或克隆 React 拥有的节点。
- 权限、计划、命令、附件、录音、工作区/预设与任务控制保留原槽位、回调与禁用条件。窄屏只能重排，不能为截图隐藏功能。

## 布局和构建

模型和强度菜单保持固定外框，窄屏/短屏内滚动；长名称和说明在预留区域内变化。深浅主题沿用 DSH 主题变量，动画遵从减少动态效果和页面可见性。

展示代码在 tools/workspace-ui；prepare-workspace-ui.py 从锁定 0.2.1-rc.2 模块精确锚点生成补丁，交由原 RuntimeTools 补丁链应用。移动插件差异通过原上游锁定补丁入口生成。不得只修改 node_modules 或生成包而漏掉可重建来源。

## 工作环境调查与修复

用户截图显示 glob 无法启动 ripgrep；只读 pwd/ls 因不存在一次性审批通道被拒；web fetch failed；若干推测的依赖和 lock 路径不存在。

- 用户提供的旧设备日志明确记录 bxroot 的 LD_PRELOAD。原分类器把所有预加载都视作未知命令，截图中的 `pwd && printf '\nTop-level entries:\n' && ls -la` 因而被误判；完全权限的 never 策略又不提供一次性审批。现在 Java 将已按签名原生锁核验的引擎 SHA 传入运行环境，策略仅在 Android ARM64、精确 APK 库路径、完整字节摘要、当前进程已加载映射、单一预加载值全部吻合时识别该引擎。任意额外库、未知启动钩子、删除、覆盖和未知脚本继续保留原确认要求。
- 原正则还会把 ENVIRONMENT 等普通变量名误当 shell ENV；改为匹配真实钩子键名。
- 同包 ARM64 搜索回归进一步复现：三个新 rg 均已退出并从 `/proc` 消失，但 bxroot 对已回收编号的 `kill(id, 0)` 返回 EPERM，原 subprocess 因此无法完成退出等待。修正固定原生 overlay：仅对账本中已知编号的零信号查询转交内核，真实信号及未知编号继续原判定；编号被复用时仍返回内核实际存在/权限结果，不把 EPERM 伪装成已退出。增加 C 断言及真实引擎的 PID/进程组 ESRCH、真实信号 EPERM、搜索及等待清理回归。
- 从实际 v183 APK 检查到 npm 附带的 ARM64 rg 为静态 ELF；bxroot 当前严格执行路径明确限制多线程进程的静态子进程。Android 改用固定 Ubuntu 14.1.0-1 的 glibc 动态版本，仍由原 rc2 subprocess/search 处理 argv、超时、取消、限额和结果解析。原 npm 文件保留，桌面选择不变。制备验证现有 noble 签名 InRelease、索引、deb、二进制和版权摘要；不修改 Ubuntu base10。独立 ARM64 Linux CI 必须用同次 APK 实测旧程序失败、新程序搜索成功，才允许签名。
- 网页抓取失败的原始原因未出现在截图中，不能凭 `TypeError: fetch failed` 断言是 DNS、证书或服务器问题。本次只补出有界的原因错误码，保持取消/超时分类、网络地址检查和请求次数。它是诊断改善，不宣称已修复未知网络故障。
- 推测的 Three.js 安装位置、lock 文件缺失本身不能证明环境损坏；恢复目录发现能力后应以实际项目内容为准，不给用户项目强装依赖。
