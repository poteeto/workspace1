# DSHA v182：普通关闭后重新打开

用户确认的复现步骤是：打开软件，清掉后台，再次打开，就出现“上次维护未完成”。用户并没有发起环境维护。v180 日志里的普通运行记录缺少退出证明；这说明上次运行结果未确认，不能据此认定环境损坏或文件维护中断。

## 修改

- `HostMaintenancePending` 只读取真正会切换或恢复文件的维护记录。普通运行历史及其旧恢复检查点不再把主界面、普通 Web 启动、终端和插件查询统一封锁。
- `BoundedGuestSessions` 继续保留未知结果的原记录，不删除，不写入虚假的 ECHILD 或业务成功。环境替换、恢复备份、重建等操作依然通过原有完整停止屏障；这次没有放宽它们的文件覆盖条件。
- 当前环境通过原有完整、健康和数据兼容检查时，未知的旧运行可延后自动替换，不再为了更新强制进入维护页。未安装、实际损坏、不兼容或真正未完成的维护仍走原来的安装/恢复路径。
- 旧版本已保存失败的“恢复中断维护”页面，在没有真正待恢复操作、环境健康且没有显式查看/重建请求时，恢复到正常界面。历史失败记录保留。
- 沿用 v180 起的固定 GitHub 签名。版本码 182，版本名 `0.2.32-20261023.1820-dsh0.2.1-rc.2`。

## 验证设计

- JVM 使用报告中的 UUID 和相同三个文件格式，检查连续 30 次重新读取不会触发维护门禁，也不会修改个人文件、旧记录或产生成功回执。
- 覆盖旧的同次开机恢复检查点、真实中断的文件恢复、无法读取的维护日志，以及正常重新进入不授予文件覆盖权限的情况。
- Android 模拟器使用实际应用进程：启动真实长任务，结束应用并重新打开。每轮核对上个应用进程已结束、原记录与个人文件保持、实际 MainActivity 不被维护门禁跳转。仅为隔离本次门禁测试使用既有 debug `skip_extract` 绕过未安装的 Ubuntu；不绕过维护判断，不冒充完整 DSH 对话、安装或原用户手机验收。
- GitHub 完整构建、Standard/Low 单测和 Release Lint、Android 回归及固定证书签名须全部通过后，才发布可安装 APK 到 Releases。

## 边界

本次修复的是把普通运行中断误判成环境维护的问题。缺失的旧任务结果仍为未知，不能追溯改为成功；文件替换仍需确认旧任务完全结束。没有连接或操作用户的 realme 手机；不能将模拟器通过写成该手机已经恢复。真实 DSH 会话和外置文件没有进入本次测试夹具。
