# DSHA v181：控制连接中断后的原生退出证明

## 问题和边界

v180 的 realme Android 16 诊断记录包含一条普通 V2 会话：有出生身份、意图和协议记录，缺少 `tree-empty`。两条能力探测及隔离试运行有各自的正常闭合证据。日志没有核验当前进程存活，也没有记录首次断线现场，不能将某一种系统终止方式写成已确认根因。

代码可以确定的故障路径是：监督器取得 `waitpid(-1, __WALL | WNOHANG) == -1 / ECHILD` 后，原先仅通过控制 socket 通知 Java，Java 收到通知才落盘。连接在 START 前后或子进程退出时断开，会造成实际未派发/已经闭合的会话缺少持久证明；旧恢复机制随后只能建立等待重启的检查点。

## 实现

- Android 启动时传入本次记录目录。监督器逐层 NOFOLLOW 打开并固定目录描述符，核对目录所属 UID、协议、UUID 和 self-stat 对应的 PID/出生时间/SID，之后才允许启动 guest。
- 监督器取得真实 ECHILD 且确认 subreaper 后，自己写入和 fsync 回执，再发布到 `tree-empty` 并 fsync 目录。只有完成持久发布后才发送 socket 通知。
- START 前断线也会尝试核对已经保存的出生身份，保存未派发回执；没有有效身份时不能伪造证明。
- Java 连接泵异常后可以读取稍后才到达的原生证明，确认原监督进程退出后再收尾。连接丢失不再改变已经证实的业务退出码。
- 复用 V2 证明格式。已有不同证明不覆盖；临时文件、SID 空或单个 PID 消失都不能代替完整证明。已完成的检查点继续按原有核验路径归档。

新版本沿用 v180 的固定 GitHub 证书，覆盖安装 v180 可以保留应用数据。没有修改个人文件、清除用户数据或操作真实手机。

## 仍需明确

此修改补齐可复现的证明丢失路径，不能追溯生成旧 v180 已丢失的 ECHILD。旧监督器已死亡且从未保存证明时，仅凭 PID 不在或 SID 为空无法证明所有脱离 SID 的后代已经消失。不能将新回归通过写成旧手机记录已经解除，也不能通过删记录或伪造业务成功解除维护。

真实设备恢复及旧记录处置仍待核验。固定证书 SHA256：`c61f876e7dc688a52484b9a4da38040acc193ffec5f329b0511a32014367b601`。
